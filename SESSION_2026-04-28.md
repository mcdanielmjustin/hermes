# Session 2026-04-28 — Adaptive Distractor Quality Matrix

**Status:** architectural redirection in progress. P0 plumbing + P-1 measurement underway.

## Why this session matters

This session committed the project to a **parametric architecture** for distractor-quality gating, replacing the one-size-fits-all rule that had been ratcheting toward over-tightening. The change is foundational: every subsequent session in this codebase should treat the decision matrix in `pipeline/distractor_policy.py` as the single source of truth for "should this distractor be flagged?" — not the audit prompt alone.

If you're picking up this work in a fresh session, read `C:\Users\mcdan\.claude\plans\should-we-have-a-graceful-dolphin.md` first for the full plan; this doc gives you the *why* and the empirical record that motivated it.

## The conceptual breakthrough

The user identified that our `StemEliminableDistractorGate` (introduced earlier this session) conflates two distinct failure modes:

- **English-proficiency gap (BAD distractor):** student rejects the option by lexical pattern-matching the stem text. No concept knowledge required. Question becomes a reading-comprehension exercise.
- **Content-knowledge gap (GOOD distractor):** rejecting the option requires invoking domain knowledge that the stem doesn't explicitly state. Distractor reveals a real diagnostic vocabulary or framework deficit when chosen.

The user's canonical example: stem says "imaging confirms PD diagnosis"; a distractor inconsistent with PD looks like a "stem contradiction" but is actually testing whether the student knows what PD entails. Picking it reveals a content-knowledge gap, not a reading gap.

This dichotomy is now the conceptual axis of the matrix. The audit prompt's "CRITICAL THRESHOLD" section (`scripts/audit_stem_contradictions.py:106-118`) is the first articulation of it; the matrix generalizes it across tier, domain, and content type.

## Three failure modes that motivated redesign

### 1. False positives at T4 Evaluate

T4 stems are vignettes rich enough to support assessment/synthesis. They necessarily carry discriminating detail. A "contradictory" distractor at T4 is often a synthesis or judgment error — *exactly* what evaluate-tier questions are supposed to test. Flagging these as stem-eliminable defeats the pedagogy.

Empirical observation: D7-PHY-195 (agonist/antagonist anchor) hit 60% T4 failure rate in this session's batch run. After audit-prompt tightening, the failures still surfaced because the gate had no way to recognize that the distractor's "wrongness" was content-knowledge by design at T4.

### 2. Architectural ceiling on concept-definition anchors

When the pedagogy requires the stem to define the term being tested (e.g., "intrinsic activity refers to a ligand's capacity to evoke a biological response"), distractors that try to confuse the term will inevitably contradict the printed definition. The stem's defining clause IS the answer; distractors collapse against it.

Concrete cases this session:
- D7-LEA-136-1 (retroactive interference, Mr. Gruber/Italian/Portuguese stem) — distractors A and B contradicted "no decline in Italian" and "intact Portuguese recognition."
- D7-PHY-195 M-03 (antagonist classification) — three distractors A, C, D all contradicted "produces no measurable postsynaptic activity."
- D7-PHY-195 X-03, X-04 — same pattern at T4.

These are not bugs in distractor generation. They are the *correct* distractors for the *wrong* stem shape. The fix isn't a better gate; it's either (a) a stem-rewrite that replaces the printed definition with an observation requiring the concept to interpret, or (b) skipping the gate on these cells because the pedagogy makes "stem-eliminable" tautological.

### 3. Domain mismatch — biopsychology rules misapplied to ethics

The pipeline currently has **zero domain-specific branching** beyond keyword filtering. Ethics (PETH) inherits BPSY's mechanism-application stem patterns, prompts, and gate logic. But ethics questions test framework application — comparing legal scope, applying ethical principles to scenarios, recognizing exceptions. A "stem-eliminable distractor" rule calibrated for mechanism contradiction does not transfer.

This was identified as a future failure mode rather than observed empirically (we ran no PETH generations this session), but the architectural fix is the same: per-domain content-type taxonomies.

## The architecture: 4-dimensional sparse matrix

```
resolve(tier, domain_code, pedagogical_content_type, misconception_type) -> Cell
```

Where:

| Dimension | Source |
|---|---|
| `tier` | 1-4 Bloom's. Already plumbed everywhere. |
| `domain_code` | 9 EPPP domains (BPSY, PETH, LDEV, CPAT, PTHE, SOCU, WDEV, CASS, PMET). Plumbed but inert today. |
| `pedagogical_content_type` | NEW. Domain-keyed taxonomy stored in anchor briefs. |
| `misconception_type` | Per-distractor. Set by `DistractorPlannerAgent`. Six types: `similar_name`, `similar_property`, `similar_store`, `opposite_direction`, `overgeneralization`, `partial_understanding`. Currently unused by gates. |

Cell output:

```python
Cell(
    gate_action: "skip" | "strict" | "permissive" | "framework_aware",
    correction_strategy: "swap_for_content_distractor"
                       | "mechanism_inversion"
                       | "judgment_error"
                       | "rewrite_stem_to_observation"
                       | "framework_misapplication",
)
```

Resolution: most-specific cell wins, falls back through (tier, content_type, domain) → (tier, content_type) → (tier,) → DEFAULT (current strict behavior). Unclassified anchors keep today's behavior.

## Per-domain content-type taxonomies (initial draft)

The user chose **domain-keyed typology** in the plan-mode confirmation. Initial drafts:

**BPSY (mechanism-focused):**
- `concept_definition` — defining terms like agonist/antagonist where the stem must restate the criterion
- `phenomenon_application` — clinical case applies a phenomenon (e.g., Parkinson's clinical presentation)
- `structural_anatomy` — brain region function (e.g., hippocampal role in declarative memory)
- `comparative_distinction` — distinguishing between systems (e.g., declarative vs nondeclarative)

**PETH (framework-focused):**
- `framework_application` — applying APA Ethics Code to a vignette
- `legal_scope_distinction` — comparing what falls under whose authority (membership vs licensure)
- `principle_resolution` — balancing competing ethical principles
- `exception_recognition` — identifying scenarios that fall outside a rule

These taxonomies are P2 deliverables; other 7 domains are deferred until evidence demands them.

## Why this redesign now and not earlier

The user's critique: "right now, you seem to be relying on experimentation rather than reinforcement and strengthening of parameters instruction and structure and expansion of techniques and methods."

This is correct. The session's earlier arc was iterative prompt-tweaking — first add the gate, then tighten the audit prompt for hedging, then add a content-knowledge threshold, then harden the parser, then add tier-aware correction guidance. Each tweak fixed a specific symptom. None addressed the underlying conceptual gap: distractor "wrongness" is multi-modal, and a single rule cannot encode all the modes correctly.

The matrix is the structural answer to that critique. It makes distractor wrongness explicit (English gap vs content gap), makes the appropriate gate strictness conditional on context that the codebase already has (tier, domain) plus context we'll add (content_type), and gives us a place to ship per-domain customization without touching the central gate logic.

## Phase Δ — 3-class audit redesign (this iteration's deepest insight)

**Why:** validation revealed Sonnet's binary "is contradicted" judgment can't distinguish English-gap from content-gap even with relaxed-mode prompts. P1 used SKIP cells as a workaround, but SKIP loses recall on cells where a real English-gap distractor *might* slip through. The architectural fix is to ask Sonnet to classify each distractor into one of three classes — this directly implements the user's framework.

**The three classes:**

| Class | Decision rule | Action |
|---|---|---|
| `english_gap` | Student rejects via lexical comparison with stem alone; no concept knowledge needed | FLAG (quality failure) |
| `content_gap` | Rejecting requires invoking concept/domain knowledge; the contradiction is real but recognizing it requires knowing what some technical term means | PASS (this IS the test medium) |
| `clean` | No direct contradiction; distractor is a wrong-but-plausible alternative requiring concept application | PASS |

**Implementation:**
- `scripts/audit_stem_contradictions.py:PROMPT` rewritten to request per-distractor classification with explicit examples for each class. Output shape: `{"classifications": [{"letter": ..., "class": ..., ...}]}`.
- `derive_flagged_from_classifications()` shim derives the legacy `flagged_distractors` list from `english_gap` entries — preserves `--fix` mode and saved audit.json compatibility.
- `parse_response()` handles both new and legacy shapes (last-JSON-wins for self-correction, brace-depth scanning for embedded objects).
- `StemEliminableDistractorGate.check()` consumes `classifications` directly: only `english_gap` items contribute to the flag list.
- `_build_mode_addendum(cell)` semantics shifted from "be permissive" → "calibration hint about which classes are typical at this cell." Biases Sonnet toward correct classification without overriding it.
- `gate_action` enum added new value `"audit"` (the new default for cells where Sonnet's classification is reliable). SKIP cells (T4 contrast_prompt, T4 subtle_error, T2 paraphrase, T2 simple_application) migrated to `audit` with calibration hints.

**Calibration test results (cost ~$0.01):**
- Canonical english_gap (Lester wedding case): A classified as english_gap → flagged ✓ (recall preserved). C and D refined into content_gap and clean respectively — richer signal than binary.
- Canonical content_gap (intrinsic-activity stem, M-03 analog): all 3 distractors classified as content_gap → not flagged ✓ (precision recovered without losing recall).

**Live integration on PHY-184 batch (cost $0.28, 20 questions × 3 distractors = 60 classifications):**

| Class | Count | Percent |
|---|---|---|
| `clean` | 32 | 53% |
| `content_gap` | 28 | 47% |
| `english_gap` | 0 | 0% |

The distribution is intuitively right for a well-designed phenomenon-application batch: about half the distractors are pure alternatives (no stem contradiction at all → clean), and half engage with the case but require content knowledge to reject (content_gap). Zero english_gap = zero false flags. Zero parse errors. Sample classifications passed sanity:
- H-03 A "compensation through cerebellar circuits…" → clean (stem says nothing about cerebellar circuits; rejection requires knowing cerebellum doesn't compensate for BG motor loss)
- H-03 B "Lewy body accumulation buffering dopamine release" → content_gap (recognizing Lewy bodies are a consequence of PD, not a compensatory mechanism, requires concept knowledge)

**Empirical observation worth flagging:** the previously-flagged X-05 distractor (laterality issue with "ipsilateral" terminology) is no longer flagged under 3-class. On reflection this is correct — recognizing that "ipsilateral" implies "same side" requires the student to know what the term means, which is content knowledge. The 3-class audit is more accurate than binary on borderline cases involving technical terminology.

**Key insight:** the matrix's cells now serve a *different* role under 3-class:
- `gate_action`: still controls whether to call Sonnet (audit / strict / skip) and modulates the calibration hint
- `correction_strategy`: unchanged — still drives retry-loop language via `[strategy=...]` tag in failure reason
- `note`: now feeds into `_build_mode_addendum` as cell-specific calibration text, not just documentation
- The gate no longer overrides Sonnet's call. Sonnet decides; cells inform.

This is a more principled architecture. SKIP becomes rare (reserved for cells where audit is genuinely unauditable). The matrix's value moves from "override Sonnet" → "inform Sonnet + drive correction strategy."

**Implication for plan:**
- P3 (misconception_type as primary key) — still valuable as additional matrix dimension, but lower priority now that 3-class audit handles most precision/recall calibration.
- P4 (stem_rewrite retry) — still applies for genuinely structural failures where Opus needs to reshape the stem.
- P5 (per-domain framework gate) — still relevant for ethics; framework_aware mode_addendum is in place.
- P6 (push to generation prompts) — eventual; could push 3-class language into generation so distractors are born content_gap-shaped.

### The unifying principle insight

Inspection of all known patterns (original 6 + new 4-5) revealed they're surface manifestations of a single rule:

> **Master rule:** "When the stem prints ANY specific fact (directional terms / numeric values / mental states / word etymology / stated symptoms / settings / timelines / shared-feature claims / etc.), distractors must not have claims whose contradiction with that fact is detectable by reading the stem alone. The contradiction (if any) must require concept knowledge to recognize."

This unification made P6's prompt design simpler: one master rule + multi-flavored example list, rather than 6+ separate rule blocks.

### User-flagged regression risk

The user identified that a naive "don't contradict any stem fact" rule could cause Opus to OVER-correct, collapsing content_gap (the workhorse) into clean-only and losing pedagogical bite. Three safeguards designed in:

1. **Distinction framing** (not prohibition framing): "Classify into english_gap / content_gap / clean — produce content_gap or clean."
2. **Explicit over-correction warning** in the v2 prompt with a tangential-distractor counter-example.
3. **Paired examples** (english_gap → content_gap rewrites) for each pattern, showing how to PRESERVE content_gap while AVOIDING english_gap.

The A/B decision criteria were tightened to detect over-correction (content_gap rate must stay within ±5pp; clean rate rise must be ≤10pp).

## Phase 18 — Ship-Readiness Pipeline (operational quality gate before bundling)

**Why this exists.** A/B testing showed v1 ships at ~4% english_gap and v2 at ~1%. Both numbers are non-zero. Without a layer between generation and bundling, those distractors reach users. The architecture had no natural place to ENFORCE quality before the bundle script copied raw output into `PassEPPP-website/content/enrichment/`.

**Three-directory architecture.**

| Path | Role |
|---|---|
| `data/quiz/` | Raw generation output. Subject to ~4%/~1% english_gap depending on prompt version. NEVER bundled directly. |
| `data/quiz_shippable/` | Audited and (optionally) auto-fixed chapters with zero english_gap. Bundle script reads here. Manifest at `manifest.json`. |
| `data/quiz_review/` | Chapters held back because audit found english_gap above threshold and auto-fix didn't converge. Human attention required. |

**`scripts/ship_readiness.py` — the gate.** Per chapter:

1. Run the existing 3-class audit (`audit_question` from `audit_stem_contradictions.py`).
2. If 0 english_gap (or ≤ `--threshold`) → copy original to `quiz_shippable/` (READY).
3. Else if `--no-fix` → copy original to `quiz_review/` (REVIEW).
4. Else → run `fix_question` on every flagged distractor → re-audit.
   - If 0 remaining → copy fixed chapter to `quiz_shippable/` (READY via `post_fix`).
   - Else → copy original to `quiz_review/` (REVIEW, `fix_did_not_converge`).

Manifest at `data/quiz_shippable/manifest.json` records per-chapter status, `source_sha256`, audit/fix costs. Re-running on unchanged source files is a no-op (hash compare). Exit code 2 if any chapters land in review.

CLI flags: `--quiz-dir`, `--ship-dir`, `--review-dir`, `--workers`, `--no-fix`, `--threshold`, `--force`.

**`scripts/build_quiz_bundle.py` — the consumer.** Now reads `data/quiz_shippable/` by default and refuses to run if `manifest.json` is missing (helpful error directs to ship_readiness). Bypass via `--no-require-manifest --source-dir data/quiz` for cases where the gate is intentionally skipped (not recommended). Same change also fixed a pre-existing latent bug where the original glob included `*.audit.json` sidecars — added the same name-filter `ship_readiness` uses.

**`config.py`** — added `QUIZ_SHIPPABLE_DIR` and `QUIZ_REVIEW_DIR` siblings of `QUIZ_DIR`.

For the brief schema upgrade (Phase 20c), the field name needed to be unambiguous to a Claude Code instance reading the schema cold (no surrounding session context). ### Audit determinism finding

Phase 19 set `temperature=0` on the audit Sonnet call to eliminate single-pass jitter. That worked for stable cases but NOT borderline ones. During Phase 20-canary sentinel construction, two consecutive audit runs at temp=0 produced **different** classifications for two distractors:

- `QZ-PMET-AP-D1-RMS-01-1-M-01:B` ("IVs classify all 5 variables; DVs describe statistical test family"): run 1 → english_gap, run 2 → clean
- `QZ-SOCU-AP-D5-CLI-209-H-01:D` ("unrelated to racial group membership"): run 1 → english_gap, run 2 → clean

These are genuinely borderline cases where the auditor honestly cannot commit to a binary. Forcing a binary IS the source of the jitter. This finding directly motivated Phase 20b's `soft_flag` class — giving Sonnet a 4th option ("genuinely uncertain") instead of forcing a coin-flip on borderlines.

Documented in `tests/audit_sentinels.py:BORDERLINE_NOTES` so future sessions know NOT to pin sentinels on these cases until soft_flag stabilizes their treatment.

### Plan-agent review surfaced 6 regression risks

Before implementing Phase 20, I ran the design through a Plan agent to surface risks I'd missed. Six concrete risks came back; all baked into the design:

1. **`question_id` is deterministic, not content-hashed.** I had been worried that stem-rewrites would change qids and invalidate ship_readiness's cache. Plan-agent pointed out qid is a deterministic function of `(domain, anchor_id_v2, tier_letter, variant)` — rewrites preserve it. The real cache invalidation lever is `source_sha256` on the WHOLE chapter file, so rescues writing to `data/quiz_rescue/` (vs merging into `data/quiz/`) sidestep the cache entirely. Decision: rescues land in `data/quiz_rescue/`; merge into `data/quiz/` is a separate human-reviewed step.

2. **soft_flag and chapters_review must be separate dimensions.** If soft_flag bumped chapters_review, the bundle's exit-code-on-review logic would silently break. Decision: soft_flag is a per-chapter COUNT, not a status. ship_readiness manifest has `soft_flag_total` and `chapters_with_soft_flag` as advisory metrics; bundle exit code is unaffected.

3. **Two addenda appended sequentially can conflict.** Phase 20a's schema-labeling clause as a separate appended chunk could override a flavor block's "Reserve english_gap for X" carve-out. Decision: schema-labeling appended INSIDE the existing flavor block (so each flavor's full clause is one coherent text, with the schema sub-rule's universal-quantifier precondition built in).

4. **Schema-labeling clause must NOT subsume the universal-quantifier signal.** The Lester/wedding canonical case has BOTH cognitive_process flavor AND a universal "all" — naive schema clause would flip it to content_gap. Decision: explicit precondition in the clause: "applies ONLY when no universal-quantifier contradiction exists." Sentinel test (Lester/wedding) catches any drift.

5. **`extract_brief_vocabulary_terms` would tokenize discriminator labels.** The new field `discriminators` contains snake_case labels like "locus_pre_vs_post". If extract_brief_vocabulary_terms read this field, Python tokenization on underscores would inject "locus", "pre", "post" into the L3 scaffold prompt's vocabulary set, polluting downstream generation. Decision: `extract_brief_vocabulary_terms` deliberately UNCHANGED; new fields excluded from vocab extraction.

6. **Stem rewrite must re-run the FULL gate stack, not just identity gates.** I had planned to re-run apply_identity / remember_identity / understand_identity after rewrite. Plan-agent flagged that anchor-fidelity gates (which check stem against `verbatim_anchor`/`testable_fact`) also matter — a rewrite that drops a key noun phrase fails those, not the identity gate. Decision documented: rescue produces candidates; full gate-stack validation belongs in a separate (later) merge step.

3. **Rescue pipeline + un-briefed generation = cheaper, simpler, equal-quality.** The rescue strategies recover dropped questions at near-quality parity; un-briefed generation has higher pass rate; together they produce roughly the same final ship-ready rate as briefed-with-rescue at lower cost. The "concept-engagement quality" wins from briefs (BPSY DLB pilot) don't pay for the brief authoring + lower pass rate at scale.

4. **Forward-only revert preserves option value.** All Phase 20c infrastructure stays in place; it just doesn't run on the generation path. If a future iteration discovers brief is helpful for a specific subset (e.g., only certain flavors), flipping the env var or making the check flavor-keyed is one-line work.

## Open questions surfaced this session that deserve revisiting

1. **Sonnet self-correction in stream** — fixed by parser hardening, but the underlying behavior may recur in other audit contexts. If the parser hardening pattern works well, consider extracting it to a shared utility module in `pipeline/`.

2. **Recall vs precision calibration on borderline cases** — H-05 ("early Parkinson's, tremor only after total depletion") was flagged once, then suppressed by the content-knowledge threshold. Whether this is correctly classified as content-knowledge or as lexical-reasoning is genuinely ambiguous. May need a "soft-flag" tier between "flag" and "no-flag" — surface as a worklist item without failing validation.

3. **Stem-rewrite as a generation-time directive vs retry-time intervention** — P4 puts stem-rewrite at retry time. An alternative is to push the "use observation, not definition" rule directly into the L3 generation prompt for `(T1, concept_definition)` and `(T2, concept_definition)` cells. This is a P6 question.

4. **Question-angle field in briefs as a content-type proxy** — anchor briefs already have `question_angles[].type` (definitional, mechanism, comparison, exception, scope, clinical_application, neuroanatomical). This is more granular than the proposed 4-bucket content-type taxonomy. Consider whether `pedagogical_content_type` should be derived from question_angles rather than added as a new field. Trade-off: derived field is automatically populated for all briefs; added field needs backfill.

5. **Unused misconception_type signal** — every saved question has `misconception_type` per option, but no gate consumes it. P3 fixes this, but the signal is already 4,261-questions deep. There's an immediate observability win: emit per-misconception-type pass/fail rates as part of P-1 cell coverage.
